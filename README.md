# Happ → Forkop

Вставьте `happ://crypt5/…` в веб-интерфейсе роутера, выберите секцию и нажмите «Добавить в Forkop». Дополнение расшифрует адрес и создаст подписку. Дальше Forkop самостоятельно скачивает серверы и обновляет их по расписанию, в том числе после перезагрузки.

## Установка

Первая версия рассчитана на OpenWrt с LuCI, Forkop с форматом конфигурации **2.0.0**, процессор **aarch64 или x86_64**. Установщик проверяет эти условия. Другие версии Forkop и архитектуры требуют адаптации; автоматически он их не обновляет.

Вставьте в SSH-консоль роутера от root одну команду:

```sh
wget -O /tmp/happ-forkop-install.sh https://raw.githubusercontent.com/future-username/happ-forkop/main/bootstrap.sh && sh /tmp/happ-forkop-install.sh
```

Она скачает архив дополнения, распакует его во временную папку и запустит установщик. Установщик скачает hpwnr и проверит его SHA-256. Временная папка удаляется автоматически. Forkop и LuCI должны быть установлены заранее.

1. После установки выйдите из LuCI и войдите снова. Откройте **Службы → Happ → Forkop**.
2. Вставьте ссылку, выберите существующую секцию Forkop с действием «Подключение», задайте интервал и нажмите **Добавить в Forkop**. Если секции ещё нет, создайте её в Forkop и примените настройки.
3. Проверьте появление серверов в Forkop. Успешная расшифровка сама по себе не подтверждает, что провайдер разрешил скачивание подписки.

Для установки из локальной копии по-прежнему можно выполнить `sh /tmp/happ-forkop/install.sh`.

Ссылку не нужно отправлять в чат или сторонний конвертер: расшифровка происходит на роутере. Подписку Forkop скачивает с сервера провайдера. Для установки требуется доступ к GitHub.

## Поведение

- Создаётся одна подписка `happ_bridge`. Повторный импорт обновляет её; остальные подписки не удаляются. Выбор другой секции переносит эту подписку в неё.
- Используется штатное автообновление Forkop: 30 минут, 1, 6, 12 или 24 часа. Отдельный планировщик не нужен.
- Введённые настройки сохраняются в `/etc/happ-forkop/settings.json`. Перед изменением Forkop создаётся копия `/etc/happ-forkop/forkop.before-import`.
- Заголовки берутся из установленного Forkop: `User-Agent: sing-box/<версия ядра>`, сведения об устройстве и автоматически вычисленный X-HWID. Это позволяет провайдеру выбрать формат подписки для ядра роутера. X-HWID можно переопределить в форме. Ограничения провайдера на число устройств сохраняются.
- Повторный импорт сохраняет фильтры серверов, переопределения и маршрут загрузки подписки, настроенные в Forkop. Адрес, секция, заголовки и расписание обновляются из формы.
- При ошибке расшифровки или проверки параметров настройки Forkop не заменяются. Если применение службой не удалось, страница сообщает, что запись уже выполнена и нужна диагностика.
- Новую зашифрованную ссылку нужно вставить заново. Обычные изменения списка серверов Forkop загружает автоматически.

## Ограничения

Это первая версия, **ещё не проверенная на физическом роутере и вашей подписке**. Она передаёт Forkop расшифрованный HTTPS-адрес. Специальное шифрование тела ответа провайдера (`Encrypt-Tag`/AES), если оно применяется, здесь не обрабатывается: для него нужен дополнительный режим скачивания через hpwnr. Это отдельный механизм, отличный от шифрования ссылки crypt5.

Установщик скачивает hpwnr **v1.0.2** и сверяет встроенный SHA-256. При изменении ключей Happ может потребоваться обновление hpwnr.

Настройки и копия содержат доступ к подписке. Они хранятся вне веб-каталога; доступны root и вошедшему администратору LuCI. Каталог включается в резервное копирование OpenWrt. После перепрошивки файлы дополнения нужно установить снова.

Исходники интеграции: [Forkop](https://github.com/ushan0v/forkop), снимок `129d303e6cc879e9edc4e13c50b1f37637e69554`; [hpwnr](https://github.com/Omegaplexx/hpwnr), авторы slavrom21 и Omegaplex. Исполняемый файл скачивается отдельно и в архив не включён.

## Если в логах `i/o timeout` и `504 Gateway Timeout`

`dial tcp <IP>:443: i/o timeout` означает, что TCP-соединение с сервером не установилось вовремя. Успешный импорт Happ не проверяет доступность VPN-серверов. По такому сообщению нельзя отличить недоступный сервер от блокировки или ошибки маршрута на роутере.

1. Обновите дополнение командой установки выше и повторите импорт через **Службы → Happ → Forkop**. Это обновит заголовки ранее созданной подписки. В Дашборде Forkop обновите именно эту подписку и проверьте, появились ли актуальные серверы.
2. Имена `Main/sub7/…` в логах не совпадают с тегом `Happ`, который создаёт это дополнение. Проверьте, какая подписка выбрана в секции и URLTest: ошибки могут относиться к другой подписке. Сравните IP и порт с актуальным профилем в Happ, не публикуя ключи доступа.
3. Для `504` при скачивании `ru-blocked-geo.srs` проверьте **Настройки → скачивание списков через прокси**. Если включён прокси через секцию, все серверы которой недоступны, загрузка списков также может не работать. Попробуйте прямую загрузку либо выберите проверенную рабочую секцию, примените настройки и обновите списки. Прямая загрузка тоже требует доступности GitHub у провайдера.
4. Для проверки доступности файла по текущему маршруту роутера выполните в SSH:

   ```sh
   wget -T 20 -O /tmp/forkop-rules-check.srs 'https://github.com/ushan0v/forkop-lists/releases/latest/download/ru-blocked-geo.srs'
   rm -f /tmp/forkop-rules-check.srs
   ```

   Успех этой команды подтверждает только скачивание файла из SSH; маршрут загрузчика списков внутри sing-box может отличаться.

Если ошибки остались, нужны результаты диагностики непосредственно с роутера: состояние службы и DNS, доступность актуальных VPN-адресов и выбранный маршрут загрузки списков. Ссылку подписки и полный немаскированный конфиг публиковать не нужно. Увеличение тайм-аутов не восстанавливает недоступный сервер.
