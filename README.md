# Happ → Forkop

Импорт подписок Happ, v2RayTun и INCY в OpenWrt с LuCI и Forkop **2.0.0**. Поддерживаются зашифрованные ссылки, ссылки-обёртки и обычные HTTPS-адреса.

## Установка и обновление

Нужны root, установленный Forkop с LuCI и процессор **aarch64 или x86_64**:

```sh
wget -O /tmp/happ-forkop-install.sh https://raw.githubusercontent.com/future-username/happ-forkop/main/bootstrap.sh && sh /tmp/happ-forkop-install.sh
```

Установщик скачивает полную сборку **hpwnr v1.0.3**, проверяет закреплённый SHA-256 и наличие нужных возможностей до замены бинарника. Версия не меняется автоматически вслед за latest. Готовые сборки hpwnr для других архитектур требуют отдельной проверки интеграции.

После установки выйдите из LuCI и войдите снова: **Службы → Happ → Forkop**. Выберите секцию Forkop с действием «Подключение», вставьте ссылку, укажите режим и интервал. Нажмите **Добавить / обновить в Forkop**. Повторная установка сохраняет настройки и существующую подписку.

Для установки версии из ветки или конкретного коммита скачайте её bootstrap.sh и задайте тот же ref через переменную окружения:

```sh
wget -O /tmp/happ-forkop-install.sh https://raw.githubusercontent.com/future-username/happ-forkop/fix/subscription-headers-and-reimport/bootstrap.sh && HAPP_FORKOP_REF=fix/subscription-headers-and-reimport sh /tmp/happ-forkop-install.sh
```

## Режимы загрузки

| Режим | Кто загружает подписку | Обновление | Когда использовать |
| --- | --- | --- | --- |
| Forkop | sing-box по расшифрованному HTTPS-адресу | Штатное расписание Forkop | Обычные подписки, которые ядро понимает напрямую |
| hpwnr | Дополнение через полную сборку hpwnr | cron; локальный список передаётся Forkop | Ответ с Encrypt-Tag/AES или Xray JSON, которому нужна конвертация |

По умолчанию выбран Forkop. Существующие настройки без поля режима также используют Forkop.

В режиме hpwnr:

- Расшифровывается ссылка, затем загружается тело подписки. hpwnr автоматически обрабатывает AES-128-GCM, когда URL содержит поддерживаемый `key=keyNN`, а сервер прислал `Encrypt-Tag`.
- Используются новые аргументы `header <имя> <значение>` и `stdout`: заголовки передаются отдельными аргументами, большие результаты не теряются в побочном файле.
- Комбинация `sb uri` оставляет поддерживаемые конвертером профили в виде URI. Дубликаты удаляет hpwnr. Неподдерживаемые протоколы и настройки Xray, включая маршрутизацию и DNS, не переносятся. Если поддерживаемых серверов не осталось, импорт отклоняется.
- Forkop получает локальный файл `/etc/happ-forkop/subscription.txt`. Обновление идёт через cron каждые 30 минут, 1, 6, 12 или 24 часа; это календарное расписание по времени роутера. Нужны `crontab`, `timeout` и служба cron. Дополнение включает cron при импорте.
- Загрузка ограничена 20 секундами. Пустой ответ, ошибка загрузки или неподдерживаемый формат не заменяют прежний список и не меняют конфигурацию Forkop. При неизменившемся списке перезагрузка не запрашивается.
- Расписание использует отдельную копию успешно импортированных настроек. Несохранённые или неудачно импортированные изменения формы на него не влияют.
- При возвращении в режим Forkop удаляется только собственное задание cron. Остальные задания сохраняются.
- Загрузка идёт по маршруту самого роутера. Выбор прокси загрузки подписки в Forkop на hpwnr не влияет. Начните с обычного режима, если подписка доступна только через настроенный в Forkop прокси.

Обновить локальный список вручную без повторного импорта:

```sh
/usr/libexec/happ-forkop refresh
```

Ошибки фоновой загрузки можно посмотреть командой `logread -e happ-forkop`. Успешное скачивание не подтверждает доступность VPN-серверов.

## Ссылки, заголовки и сохранение настроек

Принимаются `happ://crypt…/…`, `happ://add/…`, `v2raytun://crypt/…`, `v2raytun://import/…`, `incy://add/…`, `incy://import/…` и HTTPS. Обёртки расшифровывает hpwnr; конечный адрес должен быть HTTPS. Обычный HTTPS-адрес передаётся без запуска режима шифрования hpwnr.

Заголовки берутся из установленного Forkop: User-Agent ядра sing-box, модель и ОС устройства, автоматически вычисленный X-HWID. X-HWID можно переопределить в форме, если провайдер требует привязку устройства. Ограничения провайдера на число устройств сохраняются.

Создаётся одна подписка `happ_bridge` с тегом Happ. Повторный импорт обновляет её адрес, секцию, заголовки и расписание, сохраняя фильтры, переопределения и выбранный маршрут загрузки. Другие подписки не удаляются. Сначала примените несохранённые изменения Forkop.

Файлы в `/etc/happ-forkop/` содержат доступ к подписке и VPN-ключи. Они доступны root, а форма с исходной ссылкой — вошедшему администратору LuCI. Каталог находится вне веб-каталога и включается в резервное копирование OpenWrt. Перед импортом создаётся `forkop.before-import`. После перепрошивки исполняемые файлы дополнения нужно установить снова.

## Если в логах i/o timeout и 504

`dial tcp <IP>:443: i/o timeout` означает, что TCP-соединение с сервером не установилось вовремя. По одному сообщению нельзя отличить недоступный сервер от блокировки или ошибки маршрута. Обновление hpwnr само по себе эту ошибку не исправляет.

1. Обновите именно нужную подписку и проверьте выбранные серверы в Дашборде и URLTest. Тег `Main/sub7/…` на исходном скриншоте отличается от тега Happ, создаваемого этим дополнением.
2. Для ошибки 504 при загрузке `ru-blocked-geo.srs` проверьте настройку скачивания списков через прокси. Если выбрана секция с недоступными серверами, попробуйте прямую загрузку или проверенную рабочую секцию и обновите списки.
3. Сравните работу подписки в Happ через тот же Wi-Fi и через мобильную сеть. Выполните на роутере:

```sh
forkop check_service
forkop check_dns
wget -T 20 -O /tmp/forkop-rules-check.srs 'https://github.com/ushan0v/forkop-lists/releases/latest/download/ru-blocked-geo.srs'
rm -f /tmp/forkop-rules-check.srs
```

Успех wget подтверждает только скачивание из SSH: маршрут загрузчика списков внутри sing-box может отличаться. Не публикуйте ссылку подписки или немаскированный конфиг.

## Проверки и исходники

GitHub Actions проверяет shell-синтаксис, изолированное выполнение импортера, расписание и сохранение прежних данных при ошибках. Отдельные проверки скачивают настоящий hpwnr v1.0.3 с проверкой SHA-256 и проверяют crypt5, заголовки, конвертацию и stdout для результата больше 15000 байт.

Проверка на физическом роутере, настоящем UCI/procd и конкретной подписке пользователя остаётся необходимой. См. [VERIFICATION.md](VERIFICATION.md).
