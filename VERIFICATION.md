# Проверка интеграции hpwnr v1.0.3

## Автоматические проверки

GitHub Actions выполняет:

- Shell-синтаксис bootstrap.sh, install.sh и обработчика импорта.
- Изолированный запуск настоящего shell-обработчика с имитацией UCI, jsonfilter, cron и hpwnr: обычный импорт, заголовки ядра, пользовательский HWID, сохранение фильтров, переопределений и маршрута загрузки.
- Загрузку через hpwnr, большие списки, обновление из успешно импортированных настроек, отсутствие reload при неизменном списке, отказ при пустом или неподдерживаемом ответе и ошибке загрузки.
- Переключение обратно в Forkop с удалением только собственного задания cron.
- Установку с имитацией скачивания: проверка хеша и полной сборки до замены существующего бинарника, сохранение старого бинарника при ошибках.
- Проверки настоящего x86_64-бинарника hpwnr v1.0.3 из релиза: SHA-256, crypt5 roundtrip, HTTP-заголовки с пробелами в значениях, JSON→URI с удалением дубликатов и неподдерживаемых секций, stdout для результата больше 15000 байт и расшифровка тестового ответа AES-128-GCM с Encrypt-Tag.

Тесты используют искусственные адреса и локальный HTTP-сервер. Настоящая подписка не требуется. Тесты реального бинарника запускаются при заданном HPWNR_BINARY; отдельный шаг workflow скачивает и проверяет этот бинарник.

JavaScript страницы LuCI и JSON ACL дополнительно проверяются локально.

## Границы проверки

Не проверены физический роутер, настоящий LuCI/rpcd, UCI/procd/cron OpenWrt, ARM64-исполнение, подписка пользователя и доступность его VPN-серверов. Изолированная имитация и Linux CI не доказывают работу этих частей на устройстве.

Режим hpwnr требует загрузки по маршруту самого роутера. Он не использует download_detour из Forkop. При обновлении локального файла обработчик запрашивает reload, но не объявляет VPN-серверы работоспособными на основании кода возврата службы.
